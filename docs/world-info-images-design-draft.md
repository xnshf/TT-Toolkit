# 世界书图片输入方案草案

## 状态

**已实现，见 [实现说明](world-info-images.md)。** 本文保留方案阶段的决策与论证，不再是待批方案。

**方案阶段记录：** 尚未批准正式开发。 用户要求先通过提问确认方案，点头后才能实施。后续授权在不打扰用户的情况下先完成可做的调研、验证与文档归档；本轮不修改运行时代码。

本轮源码证据、已有测试结果和技术阻碍详见 [宿主接入调研](world-info-images-research.md)。本文只保留最新需求和候选实施方案，不把未完成能力写成现状。

## 1. 用户已确认

| 项目 | 决定 |
| --- | --- |
| 目标 | 让 AI 真正看见绑定世界书条目的图片，不只是显示缩略图或发送 Markdown 链接 |
| 模型假设 | 按模型均具备多模态能力设计，不做能力枚举和自动付费探测 |
| 宿主范围 | 首版仅普通 Chat Completions，不包含 Agent |
| 协议 | 尽量复用宿主图片工具、消息组装和 provider 转换，不自行实现各家协议 |
| 本地图片 | extension store Blob + 世界书内附件引用 |
| 图片 URL | 下载一次，导入为本地附件；生成时不访问源 URL，不做长期远程引用模式 |
| 触发 | 与绑定条目的文字使用同一套世界书触发机制，不另做图片关键词扫描 |
| 插入位置 | 优先与原生文字一致；无法精准插入时，接受统一末尾或其它合适位置 |
| 图片失败 | 明确提示，只跳过失败图片；正常文字和其余成功图片继续发送 |
| 库存容量 | 总量提醒，不设低硬上限；单图仍检查大小和像素；库存数量不代表本轮发送量 |
| 描述 | 支持可选图片描述文本 |
| 首版排除 | 不建独立资产库 UI，不做附件打包导出 |
| 执行边界 | 未决事项先写文档，用户离开期间不追问；正式开发仍需另行批准 |

**重要区分：**多模态模型不一定接受 system 图片。优先保持条目原生位置并不意味着可以给任何原生角色直接加图；此约束由宿主 provider 转换器实际处理，详见调研报告。

## 2. 可行性摘要

已从当前宿主源码确认：

- `Message`、`MessageCollection` 为可导入的保留前端 ESM；`addImage()` 处理 Data URL、压缩和 token 估算，collection 输出宿主标准消息。
- `WORLDINFO_SCAN_DONE` 能提供最终激活集合。
- 普通 `CHAT_COMPLETION_PROMPT_READY` 可原地修改当轮消息数组，后续仍走宿主原生传输，无需另发模型请求。
- 公开 extension store 支持 Blob；无需新增宿主文件接口。

尚不能直接宣称完成：

- 原生逐条图文精准位置：宿主先合并文字，部分条目还会被正则、预设和上下文预算过滤；最终集合不等于逐条最终消息映射。
- system 角色附图：Claude/Gemini 的部分 system 提取路径明确拒绝媒体。
- 最终消息阶段附图不自动参与之前的原生预算淘汰。
- 生成/扫描事件缺少能直接绑定二者的生成 ID；其它扩展共存仍有来源歧义。

统一位置发送是用户已接受的备选，不再为了精准位置扩展成宿主补丁工程；具体安全位置与适用路径仍需落实。

## 3. 推荐的最小功能形态

在现有“世界书 / 世界书管理”条目编辑区增加图片附件：

- 本地选图、URL 导入、预览、调整顺序、删除引用、可选描述。
- 复用既有保存状态、失败恢复和草稿机制，不另建完整编辑器。
- 可关联多张图片，库存只在需要时读取元信息和当前预览，不把所有图片同时读成 base64。
- 请求中的图片只来自本轮目标条目，不写入 canonical `chat[]`、聊天 metadata 或额外长期聊天副本。
- 不改变原生关键词、概率、分组、常驻、递归或 AI 决策规则；不增加一次视觉模型调用来判断激活。
- 页面清楚区分“库存占用”和“本轮预计发送”，避免以低库存上限限制角色卡图片素材。

## 4. 存储候选设计

### 4.1 已选的持久化方式

- Blob 归插件拥有，namespace 固定 `tt-toolkit`。
- 世界书仅保存有 schema 的附件引用和可选描述，不保存访问密钥、本机路径或原始文件名。
- 表名、key、扩展字段与 schema 暂不登记为正式契约；获批后按 `docs/storage-contract.md` 登记，再实施。
- URL 在用户发起导入时读取，成功后与本地文件走同一路径。生成不再依赖 URL、重定向和源内容更新。
- 图片 MIME、可解码性、尺寸和体积需验证，不能只信扩展名或远程 Content-Type。
- 存储 Blob 不等于传输 Data URL；只在当轮构造请求时按需转换。

### 4.2 引用位置：研究后的建议，未定 schema

早期考虑书级 UID 映射；调研发现宿主原生复制/跨书移动只复制条目字段并重分配 UID，书级映射不会自动跟随。

**建议改为条目扩展字段存引用**，以便原生复制、移动和激活对象携带附件。此选择仍需正式审阅，不直接建立长期契约。

附带要求：现有 `convertEntryUserPlaceholders()` 递归转换条目字符串，图片字段必须明确排除，不允许手动保存把地址、资源 ID 或其它结构性字段当正文宏改写。不得通过要求用户关闭宏转换来规避。

### 4.3 保存与清理

- 先准备并确认 Blob，再 fresh 复验世界书，最小变更引用并回读确认。
- 保存失败保留草稿和原引用；Blob 与世界书之间没有跨文件事务，可能留下未引用资源。
- 删除引用不立即删除共享 Blob。原生复制/移动后的其它引用可能存在于未挂载的世界书，不能只检查当前书就认定资源无人使用。
- 首版不做自动全局垃圾回收；具体清理入口与影响范围需批准。若提供全功能资源重置，要明确会使未挂载世界书中的引用失效，不能称为无损清理。
- 所有清理限定在本功能拥有的 table/key，不清空整个 namespace，不扫描无关目录。

### 4.4 导出与迁移

普通世界书 JSON 导入导出能够保留引用所在的原始 JSON 字段；外部格式转换不保证保留任意扩展字段。

**单独导出世界书 JSON 不包含本地图片。** 同一宿主数据根内复制/改名可复用资源；仅把 JSON 搬到另一数据根会缺图，需提示并继续文字。首版不追加 ZIP 打包、资产库或迁移系统。

## 5. 请求接入候选

### 5.1 激活与文字实际发送的区别

原生最终激活集合是推荐的触发事实源，但存在：

- 正则将条目文字变为空。
- 对应世界书预设组件禁用。
- 深度条目或示例在后续预算阶段未进入请求。
- Outlet 没有被引用，或该轮 skipWIAN。

这些情况下不能声称“条目在激活集合就等于文字已经发送”。需要决定图片是严格依赖文字最终存在，还是按同一激活结果统一附图。此处留作待审批语义，不自行猜测。

### 5.2 图片消息构造

在内核适配器内使用宿主 `Message.createAsync()`、`addImage(DataURL)` 和 `MessageCollection.getChat()`；不手写图片内容块或各 provider 请求格式。

URL 先在导入阶段完成下载。运行期向 helper 传已验证 Data URL，并检查实际附图结果；`addImage()` 某些下载失败会吞错返回，不能把 await 返回当成功。

优先核对原生位置；无法可靠映射时使用用户允许的统一位置。统一位置应保护尾部 assistant prefill、continue nudge 和完整工具回合，不能无条件把 user 图片消息 push 到数组末尾。

只能确定安全位置时发布附图；无法识别的受影响路径保留原文字并提示，不乱改宿主消息顺序。图片描述应说明对应条目，避免与用户新发的指令混淆。

### 5.3 预算

- 使用宿主估算器，不另写各模型视觉计费公式。
- 库存量不参与本轮 token 预算；只算本轮实际选中的图片和描述、消息开销。
- 最终消息阶段不能自动重新进行宿主历史淘汰；不为图片悄悄删历史或世界书文字。
- 单图尺寸/字节限制、单轮附图额度与超量取舍顺序仍待确认。
- 超预算保持原文字并提示遗漏；不是保证所有模型都不会超上下文，现有图像估算不等于精确计费。

### 5.4 生命周期

- 每轮清空旧激活集合；扫描事件还区分 dry-run 与真实生成。
- 读 Blob、解码和构造期间，取消/切换聊天使计划失效。发布前复验 stable ID、完整聊天 ref、事务和附件快照。
- 先在局部准备图片消息，确认后一次修改原数组；失败不留下半个图片块。
- 部分读取失败仅跳过失败图片并明确提示，不阻塞原文字和其它成功图。
- 监听器对称注销；停用后不再附图，不持久化当轮请求或图像副本。
- Agent 不在首版；quiet/tool 等额外事件不能误用上一轮图片。普通、重生成、swipe、continue、群聊逐路径验收。

## 6. 提示词查看与日志的必要配套

### 提示词查看

当前查看器从 PromptManager collection 重建消息，不直接使用 prompt-ready 的实际 chat。只修改最终数组，即便调整监听顺序也不能自动同步查看器。

开发时需要同时保留原组件归因与最终消息，明确新增图片属于哪个条目；TXT 导出/搜索不得直接 JSON.stringify 全部 base64，使用明确图片占位和数量，保留所有可读文字。

dry-run 只做本地读取和估算，不访问导入源 URL，不产生付费调用或额外持久化，不把预测说成已发送。

### 日志

沿用项目现有级别和脱敏边界：取消/无附件为 info，可恢复与局部失败为 warn。仅记录固定操作、阶段、原因码、数量、字节数、字段类型和恢复动作，不记录图片、Data URL、URL、文件名、正文、原始身份或未知异常详情。

宿主 helper 自行 console 输出异常的副作用需隔离；向它传入受控 Data URL，避免调用它的远程下载分支。更改具体日志链路前按 agent-logging 技能核对，不把本文当作完成日志审计。
