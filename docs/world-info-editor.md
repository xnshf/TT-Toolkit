# 世界书管理

功能路径：世界书 / 世界书管理。源码位于 `src/features/world-info-editor/`，界面基于宿主 iframe 工作台的实际内容宽度布局，不读消息 DOM。

## 界面

桌面主区域为条目列表与编辑表单双栏，列表内可检索标题、UID、关键词与正文；筛选常驻、启用、禁用与深度注入。窄容器（640px 以下）显示列表和详情两个视图，详情有“基本内容 / 注入时机 / 高级规则”切换。正文有全屏写作模式。

正文宏按键栏位于输入框上方（普通模式在正文框上方，全屏写作在输入框与表头之间），手机软键盘从底部弹起时仍可点按。宿主外壳把被键盘占据的高度写为 `--ttk-keyboard-inset`（宿主与 iframe 各注入一次，见 `src/ui/keyboard.js`）：窄容器下详情区、正文框与全屏写作浮层据此给键盘让位，聚焦正文或触发词框后把该控件滚到键盘上方。

键盘高度取两个来源的较大值：可视视口被压缩的差值（iOS、桌面窗口），以及宿主 Android IME 变量 `--tt-ime-bottom`。Android 键盘不改变 WebView 视口，工作台的输入在 iframe 内、不会被宿主登记为 IME 目标，因此只能读取宿主默认承接节点 `#sheld` 上的该公开变量；宿主 DOM 依赖与失败策略见 `docs/host-contract.md`。键盘弹起时不缩短工作台自身，而是由详情区、正文框和全屏写作浮层让位，并保留键盘高度的尾部余量，因此正文下方没有内容时也能手动把首行推到键盘上方。滚动避让从控件最近的可滚动祖先开始，按实际可滚动余量逐层补齐，不依赖固定的容器选择器；键盘动画与宿主写入高度都是异步的，聚焦后会在短窗口内重测几次，失去焦点后不再改动滚动位置。没有 `visualViewport` 也没有 IME 变量时变量保持 0px，桌面布局不变。悬浮模式下只发布工作台实际被键盘压住的高度，工作台整体在键盘上方时不产生多余空白。

已知限制（待真机验收）：全屏写作模式依赖宿主自身的“光标可见”行为，未实机验证光标能否在文本框高度变化后立即被带回可视区；Android 之外的 WebView（iOS、桌面）仍只用可视视口差值。

世界书选取依次优先当前聊天、角色、用户设定和全局绑定，再回退列表首本；用户手动切换后保留选择。来源来自宿主 `activeWorldInfoBindings()`。列表与内容中的 Token 数是粗估值，不是宿主计数。详情正文宏按键（`{{char}}`、`{{user}}`、`[[`、`]]`、`*动作*`、`"对话"`）与全屏写作共用一套：有选区时成对标记包裹选区并保留选中，无选区时插入到光标处。移动端列表与详情互切时保留列表滚动位置。

主次关键词为独立输入区；次级关键词由 Selective 控制，逻辑数字严格对应宿主 `AND_ANY=0, NOT_ALL=1, NOT_ANY=2, AND_ALL=3`。正则标签只表示可识别的形式，并非正则校验。触发词框支持回车、英文/中文逗号成块，失焦时未成块的内容也会自动成块，避免手机输入法下输入被丢弃；成块与删除只重建词条块，输入框本身不被替换。插入位置对应宿主 0–7：角色前/后、AN 顶/底、深度、示例消息顶/底、Outlet。

数字参数（深度、顺序、概率、组权重、Sticky/Cooldown/Delay、扫描深度）只接受合法整数：清空或越界不会进入草稿（`Number('')` 是 0，直接写入会把条目静默改成 0，概率 0 还会让条目几乎永不触发），输入框标红并在失焦时回退到上一次合法值。Sticky/Cooldown/Delay/扫描深度允许留空，等同“不设置”。

## 条目图片

图片上传、预览、描述与移除已移至独立功能“世界书 / 插入图片”，不再放在正文下方。管理器只保留只读的图片徽章、计数与筛选，不负责订阅附图事件；停用管理器不影响图片功能。原有条目图片引用保持有效。详见 [插入图片](world-info-images.md)。

## 保存边界

编辑仅在内存中保存当前条目草稿，停止输入 1 秒自动保存，或点击保存立即提交。切换世界书/条目、创建、复制与开关条目前等待草稿保存；保存失败保留草稿和选中条目。关闭功能界面时尝试提交，失败的草稿在该运行时实例中保留并在重新进入时继续显示（应用重启后内存草稿不可恢复，因此写入失败时请勿退出宿主）。

窄容器下从详情返回列表前，若草稿未保存（含自动保存失败），先执行一次手动保存；保存仍失败时停留在详情并显示错误，不静默丢弃草稿。

保存只通过 `src/kernel/host.js` 接口：用 `loadWorldInfoFresh()` 在写前比对整本磁盘世界书与上次加载的快照，检测其它编辑器的变更；仅合并本次草稿中变更的条目字段并调用 `saveWorldInfo()` 一次。新增、复制、删除与开关均重新读取比对后写入；冲突时停止写入并提示用户，不自动合并外部变更。界面不会将世界书正文存入 TT-Toolkit extension store 或日志。

快照比对与键序无关（`src/kernel/snapshot.js`）：宿主读写走 `serde_json`，对象键在磁盘和响应里都被重排为字典序，客户端自己构造的对象保留 JS 插入顺序，逐字节比较会把“值没变、只是键序变了”误判成外部改动。写入成功后还会重新读取磁盘，用回读结果作为新快照——本地对象只是请求体，不代表落盘结果。因此连续编辑、新建条目、给条目补充磁盘上原本不存在的字段都不会自伤，而其它编辑器改变任何字段值仍然会被拦下。

宿主 `saveWorldInfo` 是整本写入接口，写前比对不能代替跨进程的原子事务；在“写前读取”和“写入”之间被其它编辑器修改，仍可能发生竞争。此边界需要宿主将来提供条件写入能力才能完全消除。

## 手动保存的 user 宏转换

本功能默认开启“保存时转 user 宏”，可在“世界书管理”页顶栏切换；开关立即写入 `world-info-editor-settings-v1` 并生效，无需额外保存。关闭后手动保存不再改写正文。

开启时，点击任一保存按钮（详情头部“保存条目”、底部“立即保存”、移动端“保存”），提交前会把整个条目内所有字符串字段中独立成词的 `user`（不区分大小写）替换为宿主宏 `{{user}}`，再与其它修改一次性写入。独立成词的判定是：前后不能是标识符字符（字母、数字、`_`、`-`），并整体跳过 `{{...}}` 宏与 `<user>` / `</user>` / `<user/>` 尖括号标签。因此 `username`、`user_name`、`user-defined`、`<user>` 保持原样，而 `与user独处`、`the user said`、`user,` 会被转换。

自动保存（停止输入 1 秒）与切换条目/世界书、创建、复制、删除、开关条目时的隐式 flush 都不改写正文，只有显式点击保存才触发转换。转换结果立即回显在编辑区，并在保存状态里提示转换处数；日志只记录处数，不记录正文。

功能级设置损坏或含未知字段时不猜测解析，回退默认值并在页头显示警告与“重置世界书管理设置”入口。

保存失败时页面顶部显示错误条，并提供“重试保存”与“重读世界书”两个恢复入口；未保存/失败状态下详情状态标记与窄容器顶部栏的保存标记可点，等价于立即保存一次。没有待写入内容时手动保存会提示“没有需要保存的修改”，不会看起来毫无反应。

“重读世界书”只刷新磁盘事实源与快照，不写入、也不丢弃草稿：草稿仍标记为未保存，由用户核对后再决定是否保存；只有原条目已不存在时草稿才会被丢弃，并明确提示。

保存失败会拦住切换世界书、切换条目、新建、复制、删除、开关与返回列表。此时界面提供一次明确确认（说明影响范围与“世界书不会被本次操作改写”），确认后放弃草稿退回磁盘事实源并继续原操作，不因一个写不进去的草稿永久锁死页面；无法确定写入位置或读取失败仍然只停止该操作。

结构异常的条目（例如数组或字符串而不是对象）只降级该行：列表把它显示为“结构异常”并提供删除入口，仍可浏览和删除，但不会进入编辑器改写它；选中它会给出明确原因，而不是让整本世界书无法渲染。
