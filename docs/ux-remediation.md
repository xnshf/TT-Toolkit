# UX 审查与整改记录

本文持续记录 TT-Toolkit 的综合 UX 审查结论、整改优先级与完成状态。实现以当前实际注册的聊天清洗、聊天查看、聊天导出和日志为首要范围；暂时下架的模型服务、AI 激活和冲突检测保留问题记录，恢复注册前再集中整改。

## 审查原则

- 主要操作应靠近其作用对象，在长列表中保持可达；设置页优先将保存/应用按钮放在选项前方，用区域内吸顶栏保持桌面和手机可达。
- 系统应及时说明操作是否开始、成功、失败或需要用户继续处理。
- 临时成功信息不长期占据页面；条件警告和阻断错误持续显示至条件解除。
- 危险操作必须先显示明确影响范围，再由用户确认。
- 草稿、已保存状态、预览状态和当前生效状态必须可以区分。
- 页面更新不得中断输入、丢失焦点或使用户失去滚动位置。
- 桌面和移动端都按内容容器实际宽度布局。

## 提示生命周期

| 类型 | 默认行为 |
| --- | --- |
| 成功 | 显示在当前内容区的普通布局反馈条，4.5 秒后消失 |
| 用户取消或普通信息 | 显示 3 秒后消失 |
| 处理中 | 持续显示，完成、失败或取消后被结果替换 |
| 条件警告 | 在相关内容附近持续显示，条件解除后移除 |
| 可恢复错误 | 持续显示并允许关闭；再次操作时清除旧错误 |
| 阻断错误 | 页面内持续显示，并提供恢复或重置入口 |
| 永久删除/写回 | 使用模态确认，不自动消失 |

| --- | --- | --- |

## 世界书管理：Android 软键盘避让补强（2026-10-14）

范围仅为键盘避让内核与“世界书 / 世界书管理”的避让样式；不改外壳几何、写入策略与其它功能页面。用户反馈 0.8.2 后改世界书正文时键盘依旧遮挡光标。

根因：2026-10-09 的避让只把“可视视口被压缩的高度”当作键盘高度。Android 宿主已把 IME 作为 CSS 契约提供，不再透传为 WebView 视口缩放，因此该差值在真机上恒为 0；同一个缺口也让 0.8.2 的全屏几何调整无法顺带修好键盘路径。此外滚动避让只尝试外层 `.workbench main`，在移动端布局下它不是实际滚动容器（禁止滚动），所以既没有自动避让，也因为没有尾部余量而不能手动上滑。

| 问题 | 影响与证据 | 整改与状态 |
| --- | --- | --- |
| Android 键盘高度取不到，`--ttk-keyboard-inset` 恒为 0 | 真机反馈；Android 键盘不改写视口（见 `docs/host-contract.md` 的 IME 行） | 已完成：键盘高度取可视视口差值与宿主 `--tt-ime-bottom` 的较大值，读取已核对的默认承接节点 `#sheld`，并监听该节点 `style` 变化；无该变量时行为与之前一致 |
| 键盘弹起时不缩短工作台，只凭尾部 padding 又不产生滚动余量 | 正文下方没有内容时完全无法上滑 | 已完成：详情区与表单尾部按键盘高度留出可滚动余量，全屏写作浮层同步让位；悬浮模式只发布工作台实际被压住的高度 |
| 滚动避让固定找 `.workbench main`，实际滚动容器是详情区 | 移动端该容器不滚动，避让静默失效 | 已完成：从控件最近的可滚动祖先开始逐层补齐；键盘出现是异步的，聚焦后短窗口内重测，失焦后不再抢用户的滚动位置 |

## 离开前的未保存草稿拦截（2026-10-21）

起因：切换功能会直接卸载当前功能页，`view.draft` 随闭包销毁；关闭工作台也不给任何提示。策略经用户确认：能自动保存的先自动保存，其余一律先确认；覆盖“关闭工作台、悬浮球关闭、切换功能”，功能页自己发起的关闭不询问；文案由各功能提供。

文案统一为“继续离开不会写入”，而不是“这次改动会丢失”：关闭工作台时功能仍挂载，草稿会保留到下次打开；只有切换功能才随卸载真正丢弃。两种路径用同一句话都不会误导读者的预期。若以后要“关闭即丢弃”，需要额外让功能页实现草稿重置，而不是靠文案暗示。

| 问题 | 影响与证据 | 整改与状态 |
| --- | --- | --- |
| `App.navigate` 先改路由、先卸载，再渲染新功能 | 功能页草稿只活在闭包里，切走即丢，且无提示 | 已完成：先 `await requestLeave()`；被拒绝时不改路由、不重绘、不卸载 |
| `ShellController.closeWorkbench` 是无条件 `display: none` | ✕、Esc、遮罩点击、悬浮球再点，四条路径全部静默关闭 | 已完成：改为 async，关闭前向 App 查询；拒绝时保持原样、不迁移焦点。无守卫时保持同步快路径，关闭手感不变 |
| 没有“功能 → 外壳”的草稿上报通道 | 外壳不该理解业务字段 | 已完成：`props.setLeaveGuard(guard)` 由功能页注册，`guard()` 返回是否可离开；晚于当前渲染的注册被丢弃，换页时清空 |
| 输入法取消候选会触发工作台关闭 | 组合期间按 Esc 会关闭工作台或弹出草稿确认 | 已完成：组合态和键码 `229` 的 Esc 留给输入法，普通 Esc 仍遵循草稿和模态守卫 |
| 询问期间可能叠出多个确认框 | 连点 ✕ 或按住 Esc | 已完成：`requestLeave` 复用同一个进行中的 Promise |
| 守卫自身异常会把用户锁死在工作台 | 任一功能检查函数抛错 | 已完成：兜底一次“未保存状态无法确认…仍然离开”的确认，不静默丢弃也不锁死 |

各功能的判定与文案：

| 功能 | 判定 | 行为 |
| --- | --- | --- |
| 世界书管理 | `runtime.state.dirty` / 保存失败 | 先尝试手动落盘；写入成功直接离开，失败才确认是否不保存离开 |
| 聊天清洗 | 草稿与已保存设置的深比较 | 确认后不写入 |
| 聊天导出 | 既有 `view.dirty` | 确认后不写入 |
| 日志 | 草稿（含容量 MiB 值）与已保存设置比较 | 确认后不写入 |
| 模型服务 | 预设草稿与已保存预设比较 | 确认后丢弃（密钥无副本） |
| 世界书决策激活 | 既有 `dirty()` / `settingsDirty()` | 确认后不写入 |
| 界面与入口 | `draftMode !== saved.mode` | 确认后丢弃（主题即时生效，不参与） |
| 聊天查看 / 提示词查看 | 无持久草稿 | 不注册守卫 |

实现：`src/ui/leave-guard.js`（新建）、`src/shell/App.js`、`src/shell/controller.js`，以及上表 7 个功能页。提示一律复用 `confirmDanger`，不新增对话框样式。

验证：`npm run check` 通过（171 个文件语法、120 个文件行数预算、769 个测试）。新增测试覆盖：拒绝后保持当前功能与路由、允许后正常切换且丢弃陈旧守卫、并发请求只问一次、守卫抛错时兜底确认且不泄漏错误详情、外壳在拒绝时不隐藏工作台、模型服务与日志在“未改动”时不得打断用户。未做真机验收。
