# 插入图片

功能路径：世界书 / 插入图片（`world-info-images`），默认启用，独立于世界书管理器。源码位于 `src/features/world-info-images/`。

## 使用

1. 选择世界书和条目。
2. 上传 PNG / JPEG / WebP，或从 http(s) URL 一次性导入本地副本。不再接受 GIF。
3. 手动填写“图片描述（随图片发送给模型）”。描述可留空，不从正文自动生成。
4. 停止输入 1 秒自动保存，也可用页面前方吸顶操作栏立即保存。

界面按实际内容容器宽度折叠为单列。描述输入和自动保存不替换输入框，保留焦点、光标和输入法组合。保存失败保留草稿，支持重试、重读后核对与明确确认放弃草稿；不自动覆盖外部编辑。

## 数据与发送

- 每条目绑定一张图片，仍复用该条目的宿主最终激活结果。未激活不发送；停用本功能停止附图但不删除绑定。
- 图片消息为独立 `user` 消息，文字为 `[世界书图片: <标题>]`，有描述时换行追加描述原文。真实发送与 dry-run 预测均包含描述；图片由宿主 `Message.addImage` 构造。
- 不改写 canonical `chat[]`、聊天 metadata 或世界书正文；描述不做 user 宏转换，不写日志。
- 图片本体沿用 `world-info-images` table 的内容寻址 Blob。引用沿用条目 `extensions["tt-toolkit"].image`，schema 1 新增可选字符串 `description`；旧引用无需重建。损坏引用显示异常，允许重新上传或明确清除，不猜测修复。
- 入库即压缩（`compress.js`），且压缩发生在内容寻址之前：`blobKey` 摘要、`sizeBytes`、预览与请求体共用压缩后的同一份字节。默认规则是长边 ≤ 1568px、总像素 ≤ 1.15MP，输出 WebP q0.82；编码后仍超 300KB 时继续降质量（最低 0.6），再不够才按 0.8 逐级缩尺寸（最短边不小于 512）。这两个上限对应服务端实际会用到的分辨率（OpenAI 缩到短边 768、Claude 建议长边 ≤ 1568 / ≈1.15MP、Gemini 按 768 切片），再大不会带来模型侧收益。
- 体积 ≤ 96KB 的图片原样保留，不做解码重编；长边与总像素已在限制内且 ≤ 300KB 的图片同样跳过。无法解码或编码时退回原始字节，导入不失败。浏览器的 WebP 编码不可用时回落到 PNG，并以实际编码格式登记 MIME 与扩展名。
- 替换图片保留描述；移除图片同时移除描述，但不删除可能被其它条目共享的 Blob。
- 图片运行时复用世界书管理器的 fresh 快照/最小变更保存链路，不启用其编辑页面、宏转换或生成期事件。写入前发现整本世界书变化则停止并保留草稿。
- 世界书管理器只保留只读图片徽章、计数与筛选，不再显示图片编辑区，也不订阅附图事件。

## 模块

- `index.js`：独立注册和生命周期。
- `page.js` / `style.css`：图片、描述和保存恢复界面。
- `runtime.js` / `image-binding.js`：草稿绑定、预览、描述与安全保存。
- `schema.js`：严格解析与引用读写。
- `compress.js`：入库压缩的尺寸上限、质量阶梯与纯净的 `fitWithinLimits` 缩放规划。
- `images.js`：格式嗅探、入库压缩接线、URL 导入、激活集合、插入位置与生成期附图。
- 宿主边界仍为 `src/kernel/host-prompt.js`；存储与宿主证据分别见 `storage-contract.md`、`host-contract.md`。

## 已知限制

- 只覆盖宿主 Chat Completions 的 `CHAT_COMPLETION_PROMPT_READY` 路径，不覆盖 Agent 组装。
- 不设单图体积硬上限，也不参与宿主文字预算裁切；压缩后仍超限时由模型方拒绝请求。压缩是入库时的有损处理，原图不保留，需要恢复请重新上传。
- 不再接受 GIF 新导入（动画无法降采样，且宿主 `compressImage` 会把它转成静态 JPEG），已存在的 GIF 绑定仍可读取与发送。动图 WebP 同样会被压成首帧。
- 压缩参数为内置常量，未暴露设置项；调整需改 `compress.js` 并对已绑定图片重新上传。
- 单图读取或构造失败仅跳过该图，保留其它内容；默认脱敏日志只记录阶段、原因、MIME 和计数，不含描述、图片字节或 URL。
- 无自动垃圾回收、物理清理或图片打包导出。仅迁移世界书 JSON 不包含图片字节。
- 原有生成内扫描来源歧义仍存在；跨进程整本世界书写入也不具备宿主原子条件写入保证。
- 实际 provider 出站图片、移动端显示及 URL 导入/CORS 仍待实机验收。

## 验证

聚焦测试：`world-info-image-injection`、`world-info-image-host`、`world-info-images-runtime`、`world-info-images-page`，及世界书管理器相关测试。覆盖旧引用、描述校验/保存/原文保持、替换保留描述、移除引用、异步上传目标变化、独立启停、真实/预测注入与输入不中断；`compress.js` 覆盖入库格式拒绝与尺寸规划。压缩本身依赖 canvas 编码，Node 测试环境只验证`无法解码时退回原字节`与规划边界。
