# 提示词冲突检测

本功能目前未注册；下文描述保留源码的行为。

“世界书 / 冲突检测”对当前 Chat Completions 预设与当前挂载世界书中的**常驻条目**做一次人工触发的语义冲突审计，并管理仅对当前聊天生效的世界书条目屏蔽。

功能定位是“配置源审计器”：分析能够可靠追溯到来源的配置文本，不声称还原最终发送给模型的完整消息数组。v1 不自动检测、不修改预设或世界书原始数据、不拦截网络请求、不执行动态模板代码。

## 检测范围

纳入检测的来源：

- 当前 Chat Completions 预设中已启用、非 marker、内容非空且参与普通生成（`shouldTrigger(..., 'normal')`）的 PromptManager 项目，顺序与宿主 prompt order 一致。
- 当前挂载世界书中启用且常驻（`disable !== true && constant === true`）的条目，按宿主四组来源（全局、角色、聊天、Persona）合并。
- 预设之间、预设与世界书之间、同一来源内部的冲突。

明确不纳入 v1 的来源：关键词或向量触发的非常驻条目、角色卡、Persona、作者注释、聊天历史与用户本轮输入、Text Completion 预设、无法安全静态展开的 EJS 或 ST-Prompt-Template 动态内容。动态模板条目在界面中标记为“无法静态检测”，不会发送给模型；世界书动态条目仍可整体加入当前聊天屏蔽计划（提示为禁用整个条目）。

## 检测流程

页面默认选中所有当前生效且可分析的来源。用户可搜索、按类型筛选、展开正文或临时取消选择；这些调整只存在于内存，不写入任何持久存储。页面实时显示预计模型调用次数（提取批次数 + 1 次比较）。

检测是两阶段、完全模型语义判断的流水线，本地代码只做收集、宏替换、分批、严格校验、缓存与展示：

1. **原子指令提取**：每批最多 30 个来源且 content 合计不超过 15,000 字符（单来源超长独立成批，不截断），按稳定来源顺序串行调用。系统指令固定为不可信数据处理规则（`PHASE1_SYSTEM_PROMPT`）。用户消息只通过 `JSON.stringify` 构造，来源正文不会被当作提示词执行。
2. **全局冲突比较**：只接收已验证的规范化指令与最小来源定位信息，JSON 硬上限 40,000 字符，超限明确失败并建议缩小范围，不截断不抽样。分类为矛盾、格式、角色、风格、优先级、冗余；严重度分高、中、低。

两条约束贯穿全程：

- 任何 schema、证据或来源集合校验失败都会让**整个批次或整个检测失败**，不产生部分报告，不覆盖旧报告。
- 第一阶段结果按 `contentDigest + 协议版本` 只缓存在内存，不持久化；更换 label 但正文相同可复用提取结果。

## 报告与过期

完整成功后才原子替换当前内存报告，并自动切换到“检测结果”标签。报告摘要显示检测时间、纳入来源数、批次数与调用数、高/中/低数量。每个冲突卡片展示严重度（文字 + 图标 + 颜色）、分类、标题、涉及来源（同一来源显示“来源内部”），展开后包含规范化指令、原文证据、冲突解释、中立处理选项与来源定位；对世界书来源提供“暂存屏蔽”。

以下情况把报告标记为过期（仍可阅读，但禁用报告内的屏蔽动作）：聊天改变、预设或 PromptManager 项目改变、世界书内容或挂载关系改变、当前聊天屏蔽集合改变、重新读取后来源指纹与报告快照不同。来源变化事件只负责失效与刷新快照，从不自动发起模型请求。

若有挂载书未加载或条目列表不可读，当前来源快照失效，保留旧报告但标记过期，不继续检测或提交屏蔽变更。暂存计划仍保留；按提示在宿主打开相应的书后重新读取，再确认要应用的内容。

无冲突时显示明确结论“在本次检测范围内未发现冲突”，并列出纳入、临时排除、当前聊天已屏蔽与无法静态检测的数量，避免把“未检测”误读为“没有冲突”。

## 当前聊天的世界书屏蔽

屏蔽只通过聊天 metadata 与 `WORLDINFO_ENTRIES_LOADED` 事件生效，不修改原始世界书，也不影响其他聊天。

- 功能级设置：`main` table 的 `prompt-conflict-settings-v1`，保存 `{ schemaVersion: 1, presetId: string | null }`；`presetId` 为空时跟随“设置 / 模型服务”的当前预设。
- 聊天级数据：聊天 metadata extension `tt-toolkit.prompt-conflict`，保存 `{ schemaVersion: 1, disabledWorldEntries: [{ worldDigest, uid, contentDigest }] }`。`worldDigest` 是世界书名 SHA-256，`contentDigest` 是条目**原始正文**（未宏展开）的 SHA-256；`uid` 按宿主真实类型严格保存与比较。不保存世界书名称、正文、报告、选择或聊天 ID。
- 运行时：功能启用期间，经内核 `subscribeWorldInfoEntriesLoaded(listener, onContractError)` 验证 `WORLDINFO_ENTRIES_LOADED` 全部四个 lore 数组后，只移除 `worldDigest + uid + contentDigest` 三者精确匹配的条目，保持其他条目相对顺序；宿主事件源会等待异步监听器，因此过滤发生在提示词组装之前。条目已删除、改为非常驻或正文摘要不匹配时 fail-open（保留条目，不屏蔽）。
- 事件契约失败：负载非法时不交给过滤函数，因此即使最后一组异常也不会先修改前面的数组；只提示“本轮未应用聊天屏蔽”并记录一次 `host.event_contract_failed`（warn），不改变检测阶段、metadata 或订阅。下一次合法事件恢复处理并清除此契约提示；持续异常时提示核对宿主版本。
- 应用前验证：用户确认后重新取得聊天 stable ID 和具体 ref，与打开对话框时比较；同 stable ID 的其它分支也不写入。重新读取目标条目验证世界书摘要、UID、常驻状态与正文摘要，验证暂存动作仍与当前 metadata 一致，然后一次性写入最小变更。写入前复验失败不应用部分结果。宿主确认写入后若当前聊天已切换或不能安全同步，提示原聊天已写入、界面未同步，不重试，也不把修改带入新聊天。
- 功能关闭时保留聊天数据但暂停过滤；重新启用后仅恢复仍通过精确验证的记录。损坏或未知 schema 显式报错并停止屏蔽覆盖，页面提供重置该 namespace 的操作。

## 隐私与日志

检测会向所选模型服务发送选中来源的展开文本，这是用户显式触发的操作。报告与模型中间结果只保存在内存。日志只记录来源数、批次数、调用数、指令数、冲突数、严重度/分类计数、耗时与已知错误种类，不记录正文、evidence、世界书名称、稳定聊天 ID、访问密钥或模型原始响应。模型访问密钥仍由“设置 / 模型服务”管理，功能代码与日志不读取。

模型任务的 JSON 响应格式由 `LlmTaskService` 自动处理：优先使用该预设的 JSON 能力探测记录（保存预设时后台无感测试，见 `docs/model-services.md`）直接以最优格式起步，探测缺失或失效时按降级链（`json_schema` → `json_object` → 无 `response_format`）自适应，每次格式尝试独立短超时，挂起与空正文都会继续降级；两阶段系统提示词内置完整输入/输出 JSON 示范，普通模式下模型也能稳定输出合规 JSON。

## 已知限制

- 阶段一证据校验要求 evidence 是宏替换后正文的连续原文片段；超长来源独立成批但仍受模型上下文能力约束。
- 阶段二单次输入上限 40,000 字符；超过时只能缩小检测范围，不支持部分比较。
- 动态模板内容不会被静态执行或发送给检测模型；“无法静态检测”不等于“没有冲突”。
