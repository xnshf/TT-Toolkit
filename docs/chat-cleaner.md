# 聊天清洗

聊天清洗永久删除用户明确配置的正文区段、TauriTavern 原生 reasoning，并可选择清除其它 swipes，仅保留当前候选。它不分析、摘要或改写业务内容。

- 手动清洗每次从头到尾重新扫描全部非明确 system/tool 楼层，只分别排除最新 `M` 条 AI 和用户消息；默认 `M=0`。角色规则是否启用只决定该楼层是否产生变更，不缩小扫描范围。
- `is_system` 同时用于隐藏普通消息，`isSmallSys` 只是紧凑显示标记；二者都不决定语义角色。第一类 `role: 'tool'` 或 legacy `extra.tool_invocations` 标记的工具楼层、已知 `extra.type` 或 `extra.uses_system_ui` 标记的系统楼层不清洗；其余按 `is_user` 区分用户和 AI，包括仅有 `is_system` 标记的楼层。宿主也可能产生没有明确类型的真正系统消息，这种楼层无法与隐藏的 AI 消息可靠区分，将按 AI 处理。预览统计分别展示历史总数、可处理数、明确 system/tool 排除数以及纳入的隐藏/紧凑楼层数。
- 自动清洗分别保留最新 5 条 AI 和 5 条用户消息，并在生成结束后按聊天断点处理新增范围。用户手动编辑消息只改正文、不改变楼层结构，不构成任何清洗状态参考，不触发基线或断点变化，自动清洗照常增量运行。检测到楼层删除使某角色断点下标越界时，该角色断点回滚到顶部重新校验（幂等，重复扫描无变更）；断点未越界则忽略。
- 每个目标楼层有 swipes 时默认处理全部候选，无 swipes 时处理 `mes`。扫描范围内的 `tt_swipe_cold` 楼层先经宿主读回未加载候选，再重建计划；不读取保留范围及 system/tool 的冷候选。读回失败不阻塞其它内容，但保留未加载字段，禁止缩短冷数组。角色聊天绝对楼层 0 的 `mes` 可保存已展开的问候宏、当前 swipe 保存未展开原文；两者分别处理和复验，其它楼层投影不一致时保留该楼层正文和候选结构，不猜测修复。
- 非字符串候选、无效候选编号、非字符串 reasoning 或异常可选信息按字段局部跳过，畸形楼层按楼层跳过；其它可定位内容继续。预览显示完整警告列表，日志使用 `warn` 并包含楼层/候选索引、字段、预期约束、实际类型、原因码、源码位置、处理结果和恢复动作。无法定位当前候选时，不修改该楼层正文或清除候选；聊天身份变化仍停止当前操作，不停用整个插件。
- “规则设置 / 清除其它 swipes（仅保留当前候选）”默认关闭，作用于手动和自动清洗范围中的 AI/用户楼层，不受正文规则开关影响。启用后删除非当前候选及对应 `swipe_info`，仅保留当前候选正文/信息并重置 `swipe_id=0`；保留 `mes`、顶层 `extra` 及当前候选未知信息（其它清洗规则命中字段除外），问候原文宏不被当前展开正文替换。预览单独统计/展示候选删除，手动确认说明删除数量、损失范围和自行备份恢复方式。未能读回冷候选、当前候选无法定位或 `swipe_info` 不能对应数组时不清除候选。
- AI 与用户正文规则分别配置，互不交叉。

规则按列表顺序执行。双边规则删除开始标记到随后第一个结束标记；单开始标记删除到末尾；单结束标记删除开头到该标记。匹配按字面、区分大小写并天然支持跨行，不解释嵌套。

扫描只创建变更计划；冷候选读回仅填充宿主内存，不保存聊天。提交前重新验证 stable ID 和具体聊天 ref（角色分支可共享 stable ID）、目标正文/候选结构及待删除的完整候选信息；只写回计划字段，整批统一保存与刷新。手动确认绑定具体预览对象，确认期间计划被替换需重新确认。局部未完成字段所在楼层不被标记为已完成，后续自动增量可重试；成功状态保留局部警告。保存失败请求重载权威数据并提示重试，按可恢复故障记录 `warn`，不声称已造成不可恢复损失。将产生空 swipe 的手动操作需要额外确认；自动操作遇到空 swipe 时整批拒绝且不推进断点。插件不提供持久备份或撤销。

全局配置保持 v1 key/schema，新增布尔字段 `clearSwipes`。仅对已知旧 v1 缺失字段显式补齐 `false`；字段存在但非布尔值或其它损坏/未知 schema 仍拒绝并提供设置重置。设置变化纳入规则指纹，使自动清洗重新建立基线。

手动预览的永久提交栏位于变更列表之前。预览后修改保留数量会立即把该预览标记为失效并禁用提交，必须按新参数重新扫描；成功反馈短暂显示，警告与错误持续到条件解除或用户关闭。
