# 自动多候选回复设计归档（暂停）

> 状态：暂停研究，未进入实现  
> 归档日期：2026-08-25  
> 适用宿主：TauriTavern 2.2.0（核对提交 `439216353260`）

## 目标

在一次正常角色聊天回复之后，后台生成多条候选回复，并将成功结果追加为该消息的原生 swipes。候选可以使用不同模型、请求参数、世界书方案，以及受控的提示词配置差异。

本功能只面向角色聊天和 OpenAI-compatible Chat Completion；首版不考虑群聊、工具调用、图片或文件输入。

## 已确认的产品方向

- 原始宿主回复仍是实际的第一条 swipe，但不在 Toolkit 配置页显示为“候选 1”；配置页只管理额外候选。
- 自动触发范围为普通生成和 regenerate，不响应 swipe、continue、quiet 等生成类型。
- 后台候选不调用工具，使用非流式请求；成功项追加为原生 swipes，失败项保留当次会话状态并允许重试。
- 不改变原回复当前显示的 `swipe_id`。候选完成后只有用户主动滑动时才显示。
- 每个候选来源只在 `swipe_info.extra` 保存最小溯源信息：Toolkit 标记、稳定配置 ID 和显示名；不保存 URL、密钥、完整预设或详细请求参数。
- 并发默认值暂定为 2，不设置产品级硬上限；运行时并发不得超过实际任务数，并明确提示成本和服务限流风险。
- 配置分为全局默认和聊天级设置。聊天默认跟随全局，且不复制模型密钥等底层资源。

## 配置模型探索

简单的“每个候选复制一整套表单”会造成配置漂移和敏感字段重复，不采用该设计。

当前较合理的抽象是：

- **模型预设**：拥有 API URL、模型名、密钥，以及依赖连接的附加 body、排除 body 字段和附加 headers。高级 headers 可能包含鉴权信息，必须按敏感数据处理。
- **生成链路**：引用模型预设，并描述提示词、世界书和常用采样参数等生成差异。
- **候选计划**：由若干额外候选或链路引用组成；原始宿主回复不出现在计划编辑器中。
- **聊天级配置**：默认引用全局资源和计划；具体继承、聊天专用链路及候选列表覆盖方式尚未定稿。

界面倾向使用配置包卡片，不采用宽表格矩阵。卡片需要同时显示“当前来源”和“最终生效值”，以便区分跟随全局、引用共享链路和局部覆盖。

## 宿主能力与关键限制

- 宿主原生 `n` 已能让部分 OpenAI-compatible 来源一次返回多个 choices，但不能表达不同模型、预设或世界书的候选。
- 宿主 `Generate()` 依赖全局生成状态、UI、abort controller 和 canonical `chat[]`，不能直接并行调用多次。
- `getContext().generate()` 是串行安全包装，也会完整重跑生成流水线，不适合零副作用的多路候选。
- 宿主内部存在可用于 headless 组装 Chat Completion prompt 的函数，也存在仅在特定内部模式下产生的冻结输入快照；普通生成目前没有足够稳定的公开快照契约。
- `GENERATION_ENDED` 事件会等待监听器，监听器中不能同步等待下一次生成，否则可能形成事件死锁；后续工作必须延迟调度。
- 世界书可以通过现有扫描机制重算，并以临时监听器调整参与扫描的书和条目；监听器必须严格限定作用域并始终注销。

## 插件兼容与克制边界

完整重跑每条候选的提示词生成流程会让第三方插件重复注入、重复计算或产生外部副作用，因此不可接受。

候选变化应分为三档：

1. **最终请求克隆**：只切换模型或修改采样/附加请求参数。直接复用第一次生成的最终 messages，能完整保留插件注入和正则处理结果，风险最低。
2. **受控结构重组**：改变世界书方案，或改变同一提示词预设内的提示项开关和顺序。复用第一次生成的结构化输入，不再次广播插件注入事件，也不再次执行预设正则。
3. **切换完整提示词预设**：目标预设可能改变历史插入位置、提示顺序、格式规则、正则和插件锚点。冻结旧预处理结果后切换结构会产生混合语义，当前不应宣称为完整兼容。

如果未来实施受控结构重组，应设置“等价性闸门”：先用原配置从冻结快照重组一次，再与宿主实际发送的最终 messages 比较。只有等价时才运行结构型候选；不等价时仅运行最终请求克隆型候选，并说明存在无法安全复用的晚期插件修改。

## 暂定的保守首版

- 支持模型切换和请求参数调整。
- 支持世界书方案变化，以及同一预设内已知提示项的开关/顺序变化，但前提是能取得稳定结构化快照并通过等价性校验。
- 插件注入和预设正则只执行一次，后续候选沿用主生成结果。
- 暂不支持切换完整提示词预设；若未来支持，应明确标注为“仅应用提示结构”，不能暗示会执行目标预设的全部正则和插件钩子。

## 暂停原因与恢复入口

主要困难不是并发请求本身，而是同时保证提示词结构变化、插件单次注入、预设正则语义和全局/聊天级配置 UX。当前宿主公开契约不足以稳定取得普通生成的可重组快照。

恢复研究时优先完成：

1. 与 TauriTavern 讨论一个只读、无行为变化的生成快照公共 API/事件，至少提供普通生成的结构化输入和最终请求快照。
2. 用常见注入插件验证“结构快照重组 + 不重放事件”的行为，并定义等价比较的规范化字段。
3. 先实现只修改模型/请求参数的最小原型，验证候选写入、取消、失败重试和聊天身份复验。
4. 在原型稳定后再确定生成链路、全局默认和聊天级覆盖的数据 schema 与交互。
